# 고려사항

[← README](../README.md)

README에는 아직 안 넣었지만 검토 중인 기능이랑 아이디어.

## 대상

- 변리사 1차 (민법개론), 변호사시험 (민사법)

## 조문·색인

- 조문 화면에서 관련 기출도 같이 보기
- 법 개정되면 바뀐 부분 diff로 보여주기
- 개정된 조문으로 만든 학습 카드에 "개정됨" 표시

## 빈칸 채우기

- 자동 생성할 때 법률용어 사전에 있는 단어도 빈칸 후보로
- AI로 빈칸 추천 (기출에 자주 나온 표현 우선)
- 난이도에 "항 전체" 단계 추가 (키워드 → 구절 → 항 전체 → 조문 전체)
- 동의어는 허용 목록 만들어서 정답 처리
- 틀린 부분은 원문이랑 대조해서 표시
- 틀린 조문 말고 오래 안 본 조문도 복습 큐에 넣기

## 판례

- 쟁점 ↔ 판례 짝 맞추기 모드

## 기출

- 선택형에서 틀린 지문에 연결된 조문은 복습 큐로
- 답안 첨삭: 빠뜨린 쟁점 짚어주기, 루브릭 점수
- AI 답안은 문제별로 미리 만들어 두고 캐싱 (비용)
- 사람이 검토한 답안은 "검수됨" 표시

## 학습 관리

- 즐겨찾기, 조문 메모는 붙임. 남은 것: 조문 안 하이라이트
- 통계: 판례 정답률, 편·장별 취약 영역 히트맵
- 시험일 D-day 기준으로 하루 학습량 나누기

## 나중에

- 두문자·암기 문구 공유
- 오프라인 지원

## 회원

- 로그인 시도 횟수 제한 (지금은 없음. 배포 전 필수)
- 비밀번호 재설정, 이메일 인증 (메일 발송 서비스 필요)
- 소셜 로그인 (구글·카카오). 붙일 땐 Auth.js나 arctic
- 회원 탈퇴, 비밀번호 변경 화면
- 만료된 세션 정리 (지금은 조회할 때 무시만 함)

## 데이터 구조

- Law = 법령, LawVersion = 시행일 기준 버전, Exam = 시험 종류·연도·과목

## 기술

- 법령정보센터 API 수집은 붙임 (`npm run law:fetch`). 남은 것: 배치(cron)로 시행일 확인해서 새 버전만 추가, 배포 서버 IP 등록, 상업적 이용·출처 표시 조건 확인
- PostgreSQL 전문검색
- 모델은 용도별로 나누기: 답안 생성은 Opus, 빈칸 추천·태깅 같은 대량 작업은 Haiku
- 프롬프트 캐싱
- 법령 API 동기화용 배치 스크립트

## 참고

- AI 답안에는 "참고용, 틀릴 수 있음" 문구랑 인용 검증 결과 같이 표시

## 개발 중 주의할 점

실제로 겪으면 [트러블슈팅](TROUBLESHOOTING.md)에 기록.

- 법령 API 인증키 승인, 서버 IP 등록
- API 응답 파싱: 항목이 1개면 배열 대신 객체로 올 수 있음
- Windows 한글 인코딩: PowerShell 5.1 `Set-Content` 기본 인코딩이 UTF-8 아님
- 조문 파싱: "제○조의2" 같은 가지 조문, 삭제 조문, ①② 항 번호 기호
- 법 개정 후 빈칸 위치(offset)가 안 맞는 문제
